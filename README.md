# NASA Space Apps Challenge 2026 — Calgary

Team: Hasnain, Raida, Shahmeen, Farhan.

## Mission
Choose an official 2026 challenge, build a reproducible and scientifically defensible prototype, and submit a compelling demonstration.

## First actions
1. Read `docs/challenge-research/README.md`; shortlist official challenges.
2. Confirm roles in `docs/team-roles.md` and event requirements with organizers.
3. Record sources in `SOURCES.md` and data provenance in `data/README.md`.
4. Agree on a single MVP and measurable success criteria before coding.
5. Build the smallest working end-to-end demo, test, then polish.

## Structure
- `docs/`: research, methodology, team responsibilities, evaluation, pitch.
- `data/`: data inventory and usage rules (avoid committing large datasets).
- `src/frontend/`: user interface.
- `src/backend/`: APIs and application logic.
- `src/analysis/`: reproducible scientific analysis.
- `tests/`: automated tests.
- `submission/`: final copy, demo script, and evidence.

## Working agreement
Use short-lived feature branches, pull requests, one reviewer, and a functioning main branch. Record assumptions and limitations. Never commit credentials. AI-generated output must be independently checked. Do not imply NASA endorses the project.

## Decision gate
Do not commit to a concept until challenge fit, dataset access, MVP feasibility, and verification strategy are all demonstrated.
